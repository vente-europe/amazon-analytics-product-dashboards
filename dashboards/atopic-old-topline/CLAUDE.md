# Atopic Skincare — EU Topline Dashboard

## Purpose

**Very top-level** market view of atopic-skincare products across the 4 EU markets
(**DE · FR · IT · ES**). One pooled "atopic" view — **not yet segmented** (Tom will
segment in a later pass; the merged CSVs already carry an empty `Segment` column for
that). Built on **parent-level revenue**, de-duplicated — see method below.

Registered in the hub as `atopic` (group `topline`, `template: standalone`).

## Data source & layout

- `data/x-ray/raw/` — the 8 raw Helium 10 X-Ray exports (2 keyword searches per market):
  - DE: `h10-atopic-DE-1.csv`, `h10-atopic-DE-2.csv`
  - FR: `h10-atopic-FR-1.csv`, `h10-atopic-FR-2.csv`
  - ES: `h10-dermatitis atópica-ES-2.csv`, `h10-piel atopica-ES-2.csv`
  - IT: `h10-pelle atopica-IT-1.csv`, `h10-pelle secca e atopica-IT-2.csv`
- `data/x-ray/atopic-{CODE}.csv` — **merged + ASIN-deduped per market**, generated by the
  build. Has an empty **`Segment`** column inserted after `ASIN` (3rd-after convention)
  ready for Tom to fill in. No ASIN is dropped here.
- `_build_atopic.py` — the whole pipeline (merge → dedup → collapse → render).
- `index.html` — the generated standalone (CSS + data + Chart.js via CDN, all inlined).

All 4 markets are **Eurozone** → everything in **€**, no currency conversion.
Each raw export has the standard 33-column X-Ray header (incl. `Parent Level Sales` /
`Parent Level Revenue`).

## Method — parent-level, de-duplicated (the Miłosz Console method)

Mirrors `Milosz-Console/.../_collapse_parent_level()`. Per market:

1. **Pool** the 2 keyword exports (market detected from the `amazon.<tld>` domain in the
   `URL` column, not the filename).
2. **Dedup by ASIN** — keep the row with the higher `ASIN Revenue` (removes the same
   product surfaced by both keyword searches).
3. **Collapse variant families to ONE value** — group surviving rows by
   `(brand, Parent Level Sales, Parent Level Revenue)`. Amazon repeats the *same family
   estimate* on every variant child, and each export shows only a *subset* of a family's
   variants, so summing ASINs both double-counts and undercounts. Each family is therefore
   counted **once** at its `Parent Level Revenue`. Representative child = highest `ASIN Sales`.
   This is also what collapses **two rows with the same parent revenue** (the user's
   "same sales-per-parent ⇒ same family" rule) into a single value.
4. **12M projection** = 30-day snapshot × 12 (flat topline multiplier).

The build logs a per-market report: `raw → ASIN-dedup → families`, 12M revenue, brand count,
and any **cross-brand PLR collisions** (families with identical parent numbers but different
brands — flagged for manual review, never auto-merged; currently 0).

## Dashboard contents (topline)

- KPI strip: Total Market 12M revenue, 12M units, Product Families, Markets, Brands
- Method callout (EN + short PL) explaining the parent-level de-dup
- Revenue by Market (bar) + Market Share (doughnut)
- Units by Market (bar) + Top Brands EU-pooled (horizontal bar)
- Market Summary table (rev/share/units/families/ASINs/brands/avg price + Total row)
- Top 20 Products per Market (country pills) — parent-level 12M revenue, `Variants` =
  visible variant children per family
- Header: per-country **Edit X-Ray** buttons (URLs are `#` placeholders until Sheets exist —
  set them in `XRAY_LINKS` in `_build_atopic.py`)

## Rebuild

```bash
cd dashboards/atopic && python _build_atopic.py
```
Re-reads `data/x-ray/raw/`, regenerates the merged CSVs **and** `index.html`.
